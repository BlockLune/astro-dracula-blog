# 读屏器手动验证协议（G9 · TB3）

本文档供 issue 人工验收（review 阶段）执行。自动聚焦行为无法由 agent 实测评屏器，按 spec §3.3 约定：**不宣称「读屏零打扰」**——页面没有可靠方式检测读屏器，自动聚焦本身可能产生正常的输入框播报；验收目标是：无本功能新增的重复播报、无焦点陷阱、无焦点回拉、可识别搜索输入及已有值、Tab/Shift+Tab 可正常离开、尊重可观测的用户操作。

## 环境要求

二选一（建议至少跑一套；两套都跑则证据更完整）：

| 方案 | 读屏器 | 浏览器 | 平台 |
| --- | --- | --- | --- |
| A | NVDA（最新稳定版） | Firefox（最新稳定版） | Windows 10/11 |
| B | VoiceOver | Safari（最新稳定版） | macOS |

部署：仓库分支 `agent/generator/2a637605f5e2`，`pnpm install && pnpm build && pnpm exec astro preview --port 4322`，浏览器访问 `http://localhost:4322/`。

## 清洁会话步骤（逐方案）

「清洁会话」= 首次入口状态归零。只在标注「清洁会话」的用例开头执行，未标注的用例**沿用前一用例状态，不得清会话**。

**方案 A（NVDA + Firefox，Windows）**：

1. 关闭 Firefox 全部窗口；重新打开 Firefox。
2. 按 `Ctrl+Shift+P` 打开私密浏览窗口（私密窗口自动有独立 sessionStorage，无需手动清理）。
3. 若坚持用普通窗口：DevTools（F12）→ 存储（Storage）→ 会话存储（Session Storage）→ 选中 `http://localhost:4322` → 右键「删除全部」→ 确认。
4. 关闭 DevTools（避免 DevTools 面板成为焦点落点干扰观察）。
5. 启动 NVDA；`NVDA+F1` 打开日志查看器，记下当前日志条数与时间。
6. 焦点位于地址栏。

**方案 B（VoiceOver + Safari，macOS）**：

1. 完全退出 Safari（`Cmd+Q`）；重新打开 Safari。
2. 菜单 文件 → 新建无痕浏览窗口（`Cmd+Shift+N`），在无痕窗口执行全部用例。
3. 若坚持用普通窗口：菜单 开发 → 显示 Web 检查器（需先在 Safari 偏好设置 → 高级 勾选「在菜单栏中显示"开发"菜单」）→ 存储 → 会话存储 → 选中站点 → 删除 → 关闭检查器。
4. 启动 VoiceOver（`Cmd+F5`）；打开 VoiceOver 实用工具记录当前状态。
5. 焦点位于地址栏。

**每个用例开头记录**：读屏器名称+版本、浏览器名称+版本、OS 版本、私密/普通窗口模式、日志条数初始值。

## 用例与期望

每个用例的「实际结果」由执行人填写；**不得预先填写「是/通过」**。期望列只描述应观察到的行为。

### S1 首入聚焦与播报（核心）【清洁会话】

1. 地址栏输入 `http://localhost:4322/` 回车，双手离开键盘。
2. 等待页面完全加载（地址栏加载指示结束）后观察。

| 观察项 | 期望 | 实际结果 | 证据 |
| --- | --- | --- | --- |
| 焦点落点 | 最终落在搜索输入框（视觉焦点环可见，读屏器播报输入框角色） | 待填写 | 录屏 |
| 播报次数 | 只发生一次 | 待填写 | 录屏 |
| 播报内容 | 可含「编辑文本 / search / 在 N 篇文章中搜索」等正常内容，N 与站内文章数一致 | 待填写 | 播报原文逐字记录 |
| 重复播报 / 整页重读 | 无 | 待填写 | 录屏 |

**必须记录**：S1 的播报原文逐字记下——这就是「正常聚焦播报」的基准证据，后续用例以它为对照。

### S2 直接打字与结果【沿用 S1 状态，勿清会话】

1. 紧接着 S1，直接输入 `vimgolf`（不点鼠标）。
2. 等待列表更新。

| 观察项 | 期望 | 实际结果 | 证据 |
| --- | --- | --- | --- |
| 输入 | 字符进入输入框；读屏器随输入播报字符 | 待填写 | 录屏 |
| 焦点 | 列表更新后焦点仍在输入框，无焦点移动 | 待填写 | 录屏 |
| URL | 同步为 `?q=vimgolf` | 待填写 | 地址栏截图 |

### S3 离开与返回（Tab 顺序）【沿用 S2 状态，勿清会话】

1. 在聚焦搜索框状态下按 Tab 一次，再按 Shift+Tab 两次。

| 观察项 | 期望 | 实际结果 | 证据 |
| --- | --- | --- | --- |
| 离开路径 | Tab 一次即离开输入框，焦点顺序自然（搜索框 → 其后第一个可聚焦元素） | 待填写 | 录屏 |
| 返回路径 | Shift+Tab 返回顺序同样自然 | 待填写 | 录屏 |
| 焦点陷阱/回拉 | 无——不会被自动拉回搜索框 | 待填写 | 录屏 |

### S4 提前交互不被抢焦点【清洁会话】

1. 地址栏输入 `http://localhost:4322/` 回车。
2. 立即（趁页面仍在加载）按 Tab 一次；为留出交互窗口，建议先在 DevTools → 网络 → 节流选择「Slow 4G」（方案 A：DevTools 网络面板；方案 B：Web 检查器网络面板；完成后可关闭面板）。Tab 后焦点应落到页首链接/按钮。
3. 等待加载完成，观察 3 秒。

**有效性前提（必须记录，否则本用例无效并重试）**：Tab 必须发生在页面加载完成（地址栏停止加载指示）**之前**——记录操作时间戳与加载完成时间戳（录屏自带时间或手机秒表均可），并记下 Tab 后焦点所在的元素名。若无法确认先后顺序，标记「无效」并重试。

| 观察项 | 期望 | 实际结果 | 证据 |
| --- | --- | --- | --- |
| Tab 时序 | Tab 先于加载完成（时间戳佐证） | 待填写 | 录屏+时间戳 |
| 焦点 | 加载完成后焦点仍在 Tab 到的位置，不被移动到搜索框 | 待填写 | 录屏 |

### S5 站内导航与刷新【清洁会话】

1. 首入聚焦后（参照 S1），用虚拟光标点击「Tags」链接进入标签页。
2. 再点「Home」返回首页。
3. 再刷新首页（F5 / Cmd+R），观察 3 秒。

**判定标准（注意：不因「听到搜索框播报」直接 FAIL）**：

- 判定对象是「**本功能新增**的自动聚焦」，不是任何搜索框播报。
- 若听到搜索框播报，先区分来源并记录：
  - **浏览器/路由器自身的焦点恢复**（如刷新后恢复原先聚焦的元素）→ 允许，记录即可；
  - **本功能新触发的聚焦**（伴随典型的自动聚焦时序：页面加载完成后焦点凭空跳到搜索框）→ 记为失败。
- 分辨方法：记录播报发生时刻相对「加载完成」的先后、播报内容是否与 S1 基准一致、以及当前页面原先的焦点在哪。

| 观察项 | 期望 | 实际结果 | 证据 |
| --- | --- | --- | --- |
| 进入标签页 | 无本功能新增聚焦/重复播报 | 待填写 | 录屏 |
| 返回首页 | 无本功能新增聚焦/重复播报 | 待填写 | 录屏 |
| 刷新首页 | 无本功能新增聚焦/重复播报；若听到搜索框播报，注明来源（浏览器恢复/本功能） | 待填写 | 录屏+来源判定依据 |

## 真实触摸设备手动核查（不可用 headless 代理替代）

以下两项需在真实主触摸设备上人工执行（平板或手机，iOS Safari / Android Chrome 均可）：

1. **首入不弹软键盘**：清洁会话访问 `http://<本机IP>:4322/`（preview 需 `--host` 暴露到局域网），页面加载完成后**不得**自动弹出软键盘、页面不得自动滚动。
2. **点按后可输入**：手动点按搜索框 → 软键盘弹出 → 键入任意词 → 结果更新、URL 同步。
