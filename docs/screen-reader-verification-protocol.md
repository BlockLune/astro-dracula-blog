# 读屏器手动验证协议（G9 · TB3）

本文档供 issue 人工验收（review 阶段）执行。自动聚焦行为无法由 agent 实测评屏器，按 spec §3.3 约定：**不宣称「读屏零打扰」**——页面没有可靠方式检测读屏器，自动聚焦本身可能产生正常的输入框播报；验收目标是：无本功能新增的重复播报、无焦点陷阱、无焦点回拉、可识别搜索输入及已有值、Tab/Shift+Tab 可正常离开。

## 环境要求

二选一（建议至少跑一套；两套都跑则证据更完整）：

| 方案 | 读屏器 | 浏览器 | 平台 |
| --- | --- | --- | --- |
| A | NVDA（最新稳定版） | Firefox（最新稳定版） | Windows 10/11 |
| B | VoiceOver | Safari（最新稳定版） | macOS |

部署：仓库分支 `agent/generator/2a637605f5e2`，`pnpm install && pnpm build && pnpm exec astro preview --port 4322`，浏览器访问 `http://localhost:4322/`。

## 前置：清洁会话

每个用例开始前：

1. 关闭浏览器全部标签页后重新打开（或新建隐身窗口）。
2. 清空站点 sessionStorage（DevTools → Application → Storage → 右键站点 → Clear）——确保「首次入口」状态归零。
3. 读屏器处于启动状态，焦点位于浏览器地址栏或空白处。
4. 记录：读屏器名称+版本、浏览器名称+版本、OS 版本、日志条数初始值。

## 用例与期望

### S1 首入聚焦与播报（核心）

1. 地址栏输入 `http://localhost:4322/` 回车，双手离开键盘。
2. 等待页面完全加载（地址栏加载指示结束）后观察。

**期望**：

- 焦点最终落在搜索输入框（视觉焦点环可见，读屏器播报输入框角色）。
- 播报只发生一次（可含「编辑文本 / search / 在 N 篇文章中搜索」等正常内容，N 与站内文章数一致）。
- 无重复播报、无整页重新朗读。
- **记录**：把实际播报原文逐字记下（这就是「正常聚焦播报」的基准证据）。

### S2 直接打字与结果

1. 紧接着 S1，直接输入 `vimgolf`（不点鼠标）。
2. 等待列表更新。

**期望**：字符进入输入框；读屏器随输入播报字符；结果列表更新后无焦点移动（焦点仍在输入框）；URL 同步为 `?q=vimgolf`。

### S3 离开与返回（Tab 顺序）

1. 在聚焦搜索框状态下按 Tab，再 Shift+Tab 两次。

**期望**：Tab 一次离开输入框（焦点顺序自然：搜索框 → 之后的第一个可聚焦元素，如「Load More」按钮/第一篇文章链接）；Shift+Tab 返回路径同样自然；**无焦点陷阱**——不会被自动拉回搜索框。

### S4 提前交互不被抢焦点

1. 清洁会话后刷新 `http://localhost:4322/`，在页面加载过程中（网络慢时更容易，可 DevTools → Network → Slow 4G 模拟）立即按 Tab 一次（焦点落到页首链接/按钮）。
2. 等待加载完成。

**期望**：加载完成后焦点不被移动到搜索框，仍在你 Tab 到的位置。

### S5 站内导航与刷新不重聚焦

1. 清洁会话首入聚焦后，Tab/回车进入标签页（或用虚拟光标点击「Tags」链接）。
2. 再返回首页；再刷新首页。

**期望**：三次转换后读屏器都不播报搜索输入框聚焦；焦点停留在正常位置。

### S6 无搜索框入口不补做

1. 清洁会话直接访问 `http://localhost:4322/en/posts/a-very-interesting-vimgolf`。
2. 用读屏器虚拟光标导航到页首链接「Home」并回车进入首页。

**期望**：首页加载后不播报搜索框聚焦（机会已在文章入口结束）。

## 通过标准（对照 spec G9）

| 项 | 判定 |
| --- | --- |
| 搜索输入可识别（角色/名称），已有 `?q=` 值被读出 | 是 |
| 无本功能新增的重复播报 / 无整页重读 | 是 |
| 无焦点陷阱、无焦点回拉；Tab/Shift+Tab 离开正常 | 是 |
| 正常聚焦播报恰一次且内容合理（见 S1 记录） | 是 |
| 视觉焦点环可见（未改 outline） | 是 |

**明确不算缺陷**：S1 中「自动聚焦产生的输入框播报」本身。这是规范允许的正常行为，记录其内容即可，不得据此判 FAIL。
