# MUL-2：首次进入站点时自动聚焦搜索框

状态：供 Mika / 实现者验收的规划稿；未实现代码，未创建或派发子 issue。

## 1. 产品背景与目标

键盘用户首次进入博客后，应能直接输入搜索，而无需点击输入框。此次交付仅包括搜索框的初始焦点行为及其必要的可访问性保护，不包括项目中的 outline 美化。

成功标准不是“每次挂载都 focus”，而是：在合适的首次入口、页面就绪且用户尚未开始操作时，将焦点交给可用的搜索框；其他情况下尊重用户、浏览器和路由器的焦点与滚动。

## 2. 仓库事实

检查基线：`e5c153e50e0ebeb12ff8c88114f1f927b7a50c04`，仓库 `BlockLune/astro-dracula-blog`。

- `src/components/ui/search-input.tsx`：共享的受控输入框，有 `label` / `htmlFor` 与 `id="search"`，没有 `autoFocus`、ref 或聚焦副作用。
- `src/components/ui/post-stack.tsx` 与 `tag-group.tsx`：复用上述搜索框，没有聚焦行为。前者异步加载搜索数据，后者直接过滤标签。
- `src/pages/[lang]/index.astro`、`tags/index.astro`、`tags/[tag].astro`：分别在首页、标签列表、单标签文章列表以 `client:load` 激活搜索模块。
- `src/pages/index.astro` 将根入口 rewrite 到默认语言首页。
- `src/layouts/base-layout.astro` 使用 Astro `ClientRouter`，HTML 带 `scroll-smooth`。不能把站内换页等同首次进入，也不能引入延迟的平滑滚动。
- `src/hooks/use-search-params.ts` 保留 `q` 参数，300ms debounce 后更新 URL，并响应历史导航。初始焦点不能改变这些语义。
- 全仓库检索 `autofocus`（忽略大小写）及显式 `.focus(...)` 未发现既有自动聚焦实现。因此按“在现有搜索框上补齐首次聚焦能力”规划，而非再造搜索框。实施前若基线发生变化，先复核，已有逻辑则原位优化。
- `package.json` 已有 `pnpm check` / `pnpm build`，未配置专门的浏览器测试套件。无需为了该功能引入新的运行时依赖。

## 3. 行为规格

### 3.1 “首次”的默认产品定义

原 issue 未定义刷新、标签页和站内导航的边界。本稿采用以下建议作为实施合同；若 Mika 选择另一语义，应先调整本节和验收用例，不由实现者自行猜测。

- 一次标签页会话的首次站点入口，最多一次自动聚焦机会；不是终身首次，也不是每次组件挂载。
- 首次直达首页、标签列表或单标签文章列表时，其现有搜索框都适用。所有现有语言入口一致。
- 首次入口没有搜索框（如文章、关于、404）则不聚焦，也不把机会延迟到随后站内页面。
- 刷新、语言切换、站内导航、前进/后退和 BFCache 恢复不再次自动聚焦。浏览器自行恢复原有焦点不算新自动聚焦。
- 被安全条件拦截也算本次机会结束，不在用户操作后突然补聚焦。正常新标签页进入形成新机会；浏览器“复制标签页 / 恢复会话”如继承会话状态，优先不抢焦点。
- 会话记录不可用时不抛异常，保守跳过自动聚焦，手动搜索照常可用。不需要账户、cookie 或跨标签页同步。

### 3.2 就绪时机与使用效果

- 初始文档加载完成、搜索框已完成客户端激活且输入事件可用后，才允许自动聚焦；两者先后顺序任意均正确，不使用固定延时猜测加载完成。
- 不必等待全部搜索数据请求完成。加载期间输入不得丢失，数据就绪后仍按现有搜索机制过滤；网络错误仍按原逻辑展示。
- 成功后用户无需点击即可输入；已有 `q` 的值不得被清空或自动全选，光标位于已有文本末尾。
- 一次成功后，输入、结果更新、异步数据完成、组件重渲染都不能再次调用自动聚焦。

### 3.3 A11y 与不打扰原则

以下保护条件优先于“自动”：

- 用户已通过键盘、指针、触摸或主动滚动开始操作，或其他可交互元素已获得焦点：跳过。
- URL 有 fragment、页面存在非初始滚动位置 / 历史恢复意图：跳过，保留锚点与阅读位置。
- 文档在后台、目标不可见、不可用或不在可视区域：跳过；不在标签页重新激活时补做。
- 默认跳过主要依靠触摸的设备，避免首屏弹出软键盘；支持键盘的桌面设备仍是本需求主场景。设备判定策略与混合设备实测结果需记录，不能声称完美检测所有硬件。
- 聚焦本身不得造成页面或可滚动容器移动，不能使用滚动到输入框来满足条件。
- 保留可访问名称、原生键盘顺序与现有可见焦点提示；不添加正数 tabindex、焦点陷阱或强制重新聚焦。不改 outline 样式。

**屏幕阅读器限制：** 网页没有可靠方式识别屏幕阅读器或其虚拟光标；自动焦点本身也可能产生正常的输入框播报。“加载完成后执行”不能保证完全不打断读屏。因此本稿的可验收含义是：不新增 live-region 重复播报、不重复移动焦点、尊重能观测到的用户操作，并通过人工读屏验证名称与离开搜索框的路径。不得宣称“所有读屏用户零打扰”。如果验收要求绝对不打断初始朗读，则必须改为用户主动触发聚焦，与无条件自动聚焦不可同时保证；这属于产品取舍，不靠设备嗅探规避。

## 4. 高层技术设计

- 复用共享 `SearchInput`，集中维护焦点策略，避免首页与标签页各写一份。
- 用现有页面生命周期、React 激活时机和浏览器焦点能力协调一次性动作；页面级首次入口识别必须覆盖无搜索框页面，并与 Astro 客户端路由区分。
- 职责分为“入口资格 / 会话机会”“加载与激活就绪”“焦点安全条件”；这些是行为职责，不要求引入三套抽象或新全局框架。
- 会话状态只记录是否已经处理首次入口，不保存搜索内容或个人数据。失效时选择不打扰。
- 生命周期结束、路由离开或资格取消后，待执行动作失效，监听器清理；不得影响路由器原有焦点管理。
- 不改搜索算法、URL 协议、内容获取、页面布局、主题、快捷键或其他表单。

## 6. Gradable criteria（逐项通过 / 不通过）

每次需要首次入口的测试使用清洁会话；测试数据选择仓库确实存在的文章标题与标签。

| ID | 场景与操作 | 通过标准 |
| --- | --- | --- |
| G1 首次入口 | 桌面清洁会话分别直达 `/`、各语言首页、标签列表及一个有效单标签页；目标可见，无交互或 fragment | 初始文档加载和客户端激活全部完成后，正常前台条件下 1 秒内 `activeElement` 为该页搜索框；期间自动聚焦最多一次 |
| G2 就绪竞态 | 分别延迟文档资源与客户端脚本；覆盖激活早于 load 和晚于 load；另延迟搜索数据 | 两个就绪条件满足前无自动聚焦；满足后仍可聚焦。输入文字被保留，数据完成后产生正确结果，无水合/运行时错误 |
| G3 输入回归 | 首次入口带有效 `?q=`；聚焦后键入一个字符，再测试清空和正常搜索 | 原查询不被清空或全选，字符追加于末尾；过滤与 URL 同步保持原语义；渲染和请求完成后无二次抢焦点 |
| G4 用户优先 | 慢加载期间分别 Tab 到链接、点击按钮、触摸页面、主动滚动；或预先让其他输入获得焦点 | 延迟工作完成后仍不跳到搜索框；既有焦点/滚动位置不被覆盖，无补做 |
| G5 首次语义 | 成功或跳过首次机会后，依次刷新、换语言、站内切页、前进/后退、BFCache 恢复；另先进入文章再去首页 | 本功能新增的自动聚焦调用均为 0；首入无搜索框页面无异常；浏览器/路由器自身的正常焦点恢复不被强制覆盖 |
| G6 安全跳过 | 分别测试 fragment、非零滚动位置、后台加载、搜索框在视口外 / 隐藏 / 不可用、会话存储拒绝访问 | 不自动聚焦，不抛异常；切回前台或条件改变后不突然聚焦；手动搜索仍可用 |
| G7 无滚动副作用 | 在固定布局下记录自动聚焦前后窗口和祖先滚动容器位置，观察随后 500ms；锚点页另作对照 | 聚焦造成的位置差不超过 1 CSS px，无平滑滑动；锚点和历史恢复保持浏览器正常行为。图片加载等布局位移单独区分 |
| G8 生命周期 | 加载未完成就离开页面，再返回；连续站内切换 10 次 | 旧页面待执行动作不抢新页面焦点；无重复自动聚焦或运行时错误，监听/任务有清理证据 |
| G9 A11y / 设备 | NVDA + Firefox 或 VoiceOver + Safari 实测一组；键盘 Tab / Shift+Tab 离开搜索框；主要触摸设备首次进入并手动搜索 | 可识别搜索输入及现有值；无本功能新增的重复播报、焦点陷阱或焦点回拉；原焦点提示可见；触摸首入无程序性软键盘弹出，手动搜索可用。记录正常聚焦播报，不能据此声称零读屏干扰 |
| G10 交付质量 | Chromium、Firefox、WebKit 的核心首次入口/导航回归；运行项目检查与构建 | 保留最小可运行浏览器回归检查（至少成功首入、提前交互取消、站内不重聚焦），提供命令及结果；`pnpm check`、`pnpm build` 通过，或明确列出复现于未修改基线的既有失败并交验收人判断；无 outline 美化及无关变更 |
